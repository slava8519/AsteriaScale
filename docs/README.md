# Карта документации

Что где лежит, насколько это актуально и в каком порядке читать. Документы на
русском, кроме корневого [README.md](../README.md) (обзор проекта),
[AGENTS.md](../AGENTS.md), [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) и
README в каталогах `assets/` и `src/AsteriaScale.RankerWorker/` — они на английском.

## Порядок чтения

- **Новому читателю:** обзор на английском — корневой [README.md](../README.md),
  руководство пользователя — [README.ru.md](../README.ru.md) →
  [ARCHITECTURE.md](ARCHITECTURE.md) → [DEVELOPMENT.md](DEVELOPMENT.md) →
  [ROADMAP.md](ROADMAP.md).
- **ИИ-агенту:** [AGENTS.md](../AGENTS.md) (Claude Code получает его через
  `CLAUDE.md`) → [ARCHITECTURE.md](ARCHITECTURE.md) →
  [DEVELOPMENT.md](DEVELOPMENT.md); задача — из [ROADMAP.md](ROADMAP.md) или
  [audit/pass-e-translation-quality.md](audit/pass-e-translation-quality.md),
  готовые промты — в [PROMPTS.md](PROMPTS.md).
- **Чтобы проверить число или решение:** [RESEARCH.md](RESEARCH.md) —
  датированный журнал измерений; протокол замеров —
  [BENCHMARKING.md](BENCHMARKING.md).

Где искать текущий статус:

- задачи продукта — две таблицы в [ROADMAP.md](ROADMAP.md): №0–12 в начале файла, №13–19 — в начале раздела «Трек II»;
- карточки аудита перевода `E` — таблица «Карточки» в
  [audit/pass-e-translation-quality.md](audit/pass-e-translation-quality.md):
  карточка закрывается только вместе с числами в `RESEARCH.md`;
- числа и выводы измерений — [RESEARCH.md](RESEARCH.md), более поздний раздел
  уточняет более ранний;
- закрытые проходы аудита A–D — [AUDIT-ROADMAP.md](AUDIT-ROADMAP.md).

Пути `artifacts/…` в документах — локальные результаты прогонов: каталог
`artifacts/` исключён из git, в репозитории этих файлов нет.

## Статусы

- **Актуальная спецификация** — описывает текущее состояние кода и меняется
  вместе с ним.
- **Живой журнал** — пополняется по ходу работы; записи датированы, и ранний
  вывод может быть уточнён более поздней записью.
- **Архив** — закрытая работа; файл не обновляется и читается как история.
- **Инструменты** — инструкции к вспомогательным скриптам, окружениям и агентам.

## Термины проекта

Определения взяты из того, как термины используются в коде и документах
репозитория.

| Термин | Значение |
|---|---|
| WSD | Word-sense disambiguation — выбор значения английского слова в контексте. В Asteria это задача ранжировщика (GlossBERT или ConSeC в изолированном воркере): по контексту и английским определениям он выбирает группу смыслов или воздерживается при разрыве оценок меньше `0.25`. |
| outcome, GroupId | В плане ранжировщика outcome — группа смыслов с одинаковым видимым русским результатом, GroupId — её номер, равный индексу в `visibleTranslations` (инвариант 2 в [ARCHITECTURE.md](ARCHITECTURE.md)). В бенчмарках «исход смысла» — итог проверки перевода: `correct`, `wrong`, `mixed` или `unresolved`. |
| MWE | Multi-word expression — устойчивое многословное выражение, которое словарь хранит одним ключом (например `if you wish`); каркас находит доверенные MWE в предложении. |
| каркас, scaffold | `TranslationScaffoldBuilder`: детерминированные термины, имена, доверенные MWE и принятые ранжировщиком смыслы всего предложения, которые TranslateGemma получает как опоры для второй строки; в карточку «Умного словаря» они не попадают. Слой `*-scaffold.*` — отдельная карта проверенных терминов только для этих опор. |
| evidence, подсказки | Выбранные смыслы в provider-neutral виде (`SemanticSenseEvidenceFactory`): английское определение, выбранная русская поверхность и отвергнутые поверхности. Источник указан в поле `origin`: ранжировщик, эвристика, единственный исход, выравнивание Tatoeba или кэш результатов; смыслы остальных слов предложения в каркасе — только принятые ранжировщиком. |
| `direct`, `smart` | Две руки бенчмарка полного перевода: `direct` — чистая TranslateGemma с официальным промтом; `smart` — production-путь второй строки с каркасом, evidence, гейтом и guard. `smart + ConSeC` — тот же путь с ранжировщиком ConSeC. |
| A, B, repair | Кандидаты второй строки: A — direct-перевод, B — независимый conditioned-перевод с выбранными и отвергнутыми смыслами, repair — не более одного адресного исправления после сравнения. |
| APE | Automatic post-editing — один дополнительный проход TranslateGemma, который правит direct-черновик с учётом контекста (длинная или ролевая реплика, скрытый контекст hook, термины каркаса). При наличии evidence вместо него запускается кандидат B. |
| gate и guard | Gate в рантайме — `SensePreservationGate`: сравнивает A и B по сохранности смысла, полярности и чисел и решает, нужен ли repair. Promotion gate (или quality gate) — заранее объявленные критерии приёмки модели или политики. Guard — `SmartPhraseTranslationGuard`: финальная проверка строки перед показом (русский текст, посторонний английский, структура); при отказе вторая строка показывает «Перевод фразы недоступен», в бенчмарке это «вердикт guard». |
| ITT | Intention-to-treat — доля верных исходов смысла среди всех случаев набора, включая непереведённые и неразрешённые (`accuracyIntentionToTreat` в `tools/translation-benchmark.py`). |
| dev201 (`mucow201`) | Открытый настроечный срез MuCoW EN→RU `mucow-wsd-smart-hover-one-per-sense-v1`: 201 случай, первый пример каждой группы смыслов. Числа на нём — настройка, а не подтверждение. |
| replication199 | `mucow-wsd-smart-hover-replication-v1`: 199 случаев, не пересекающихся с dev201 по источнику (второй пример каждой группы). Открыт один раз 17 августа 2026 для promotion gate и с тех пор израсходован. |
| blind-v3 | `mucow-wsd-smart-hover-blind-v3`: 200 случаев, создан 17 августа 2026 и не открывался; предназначен для одного заранее объявленного прогона после заморозки конфигурации. |
| holdout, frozen-наборы | `assets/Ranker/ranker-holdout*.json` и `assets/Translation/translation-holdout-v1.json`: только для однократного финального подтверждения, не для настройки; каждое открытие записывается в `RESEARCH.md` (для `ranker-holdout*` это правило 5 в `AGENTS.md`). |
| coopmat | Cooperative-matrix-шейдеры Vulkan (`KHR_coopmat`) в llama.cpp. С ними вывод TranslateGemma зависел от предыдущих запросов, поэтому продукт запускает Vulkan с `GGML_VK_DISABLE_COOPMAT=1`, а Vulkan identity получила суффикс `-nocoopmat` (карточка E17). |
| VN | Визуальная новелла. VN-слой (`*-vn.*`) — курируемый словарный слой, который перекрывает общие словари (правило 10 в `AGENTS.md`). |
